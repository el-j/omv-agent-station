AI Models, Gateway & Smart Routing

Multi-tier model redundancy, automated fallback cascades, LiteLLM gateway configuration, and model selection syntax.

🧠 Resilient AI Gateway Architecture:
The Agent Station routes all AI queries through a local litellm-proxy container on port 4000. If an upstream provider suffers rate limiting (HTTP 429) or server outages (HTTP 500/503), the gateway seamlessly cascades to the next healthy model in milliseconds with zero dropped messages.

💬 How to Select Models via Chat

You can query any specific model or use intelligent shortcut commands: 

# 1. Quick Shortcut for Google Gemini Flash:
/gemini Explain how systemd timers compare to crond

# 2. Quick Shortcut for GitHub GPT-4o:
/gpt4 Write a TypeScript interface for this JSON schema

# 3. Model Flag Selection via /chat:
/chat -m reasoning-heavy Optimize this SQL join query for 10M rows
/chat -m coder-smart Find and fix the memory leak in worker.py

# 4. Interactive Dashboard:
/models     # Displays active models with tap-to-ask inline action buttons!
/modelhelp  # Displays in-depth model documentation inside chat

🔄 Redundancy & Failover Configuration

The LiteLLM gateway configuration is defined in /usr/share/openmediavault/agent-station/litellm_config.yaml: 

model_list:
  - model_name: coder-smart
    litellm_params:
      model: gemini/gemini-2.0-flash
      api_key: os.environ/GEMINI_API_KEY
  - model_name: coder-smart
    litellm_params:
      model: anthropic/claude-3-7-sonnet-20250219
      api_key: os.environ/ANTHROPIC_API_KEY
  - model_name: coder-smart
    litellm_params:
      model: deepseek/deepseek-chat
      api_key: os.environ/DEEPSEEK_API_KEY

router_settings:
  routing_strategy: latency-based-routing
  num_retries: 3
  timeout: 45
  fallbacks:
    - coder-smart: ["github-gpt-4o", "gemini-3.6-flash"]
